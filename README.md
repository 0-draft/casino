# Casino

Two tables that live in GitHub Actions, played by whoever turns up: [blackjack](#blackjack) against a dealer, and [baccarat](#baccarat) (punto banco) against a shoe. Nothing to install, and no account beyond the one you already have: every decision or bet is an issue, and both tables are this file.

### How to play blackjack

Pick a chip to deal a hand, then hit, stand, double, split or surrender with the buttons that appear. Each click opens an issue with the decision already written in the title — press Submit, and about 30 seconds later the table above has moved and the issue is closed with a note on what that decision was worth.

There is one table and one hand at a time, so whoever clicks next is the player. A link drawn for an earlier hand is refused rather than applied to whatever is on the table now.

- Six decks, dealt down to a cut card at 75% before the shoe is shuffled
- Every card that has come out of the shoe is listed under the table. Nothing here tells you the count; counting it is the game
- Each decision is priced from the cards actually left in the shoe, and what a mistake cost is added up per player
- Every hand is kept in [.github/blackjack-log.txt](.github/blackjack-log.txt)

### How to play baccarat

Pick a spot (Player, Banker, Tie, or either pair) and click a chip in its row. The click opens an issue with the bet already written in the title. Press Submit, and about 30 seconds later the coup has been dealt by the standard tableau, the table above has moved, and the issue is closed with the result and a note on what that bet was worth.

Nothing is decided once the chip is down, so one click is one whole hand. There is one table and one hand at a time: a link drawn for an earlier hand is refused rather than played against a shoe the clicker never saw.

- Eight decks, dealt down to a cut card 16 cards from the end before the shoe is shuffled
- Every card that has come out of the shoe is listed under the table, and the bead plate shows every result of the shoe so far
- Each bet is priced exactly from the cards actually left in the shoe. The issue comes back with the value of all five spots, and what choosing a worse one gave up is added up per player
- Late in a shoe a tie or a pair bet sometimes has the edge over the house. The comment says so when it happened
- Every hand of the last 40 shoes, with each shoe's cards and road, is kept in [.github/baccarat-log.txt](.github/baccarat-log.txt)

## How it works

Each game is one script, one state file and one workflow, and the two never touch each other's files. Issue titles keep them apart: a title starting with `bj|` is a blackjack decision and one starting with `bac|` is a baccarat bet. Both workflows write README.md, so they share one queue and take turns.

| | Blackjack | Baccarat |
| --- | --- | --- |
| Game, state and renderer | `scripts/blackjack.py` | `scripts/baccarat.py` |
| The odds | `scripts/bjmath.py` | `scripts/bacmath.py` |
| State | [.github/blackjack.json](.github/blackjack.json) | [.github/baccarat.json](.github/baccarat.json) |
| Workflow | `.github/workflows/blackjack.yml` | `.github/workflows/baccarat.yml` |
| Marker in this file | `BLACKJACK:START/END` | `BACCARAT:START/END` |

Blackjack: `scripts/bjmath.py` prices each decision against the shoe. The hole card is not in the repository: the state file is public, so the dealer's second card is not drawn until it is turned over. `.github/workflows/calculator.yml` checks the calculator against all 260 cells of the published basic-strategy chart, nightly and on any change to it.

Baccarat: `scripts/bacmath.py` is the drawing rules and the exact odds of every bet, summed over every way the next four to six cards can come out. On a full eight-deck shoe it reproduces the published house edges: 1.06% on Banker, 1.24% on Player, 14.36% on Tie at 8 to 1. `.github/workflows/baccarat.yml` plays only a title in exactly the form the chips write. Any other title starting with `bac|` is closed without being played, and so is a bet from an account that has opened more than six issues in the last three minutes, so that nobody can fill the queue and hold the table.

Both tables are drawn from one set of images in `.github/cards`: the deck, the empty slot, the felt padding and the chips are shared, and each game adds its own (the face-down card and buttons for blackjack, the bet spots and bead plate for baccarat). `scripts/make_cards.py` draws all of them, and the images are committed rather than generated on each hand, so `.github/workflows/checks.yml` regenerates them on every pull request and fails if the committed art no longer matches its generator. It does the same for both tables, redrawing each from its state file.
